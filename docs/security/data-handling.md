# 数据处理与 Git 提交规范

## 数据分类

- 公开：代码、脱敏后的通用技术文档、公开接口说明。
- 内部：未公开的架构、测试记录、运营配置和成本信息。
- 敏感：医院原始资料、患者信息、咨询记录、诊疗图片、音视频、访问令牌和模型密钥。

敏感数据不得进入 GitHub 仓库，即使仓库设置为私有也不例外。

## 本地存放

本地开发资料应放在已忽略的 `private/`、`hospital-data/`、`source-materials/`、`uploads/` 或 `data/` 目录。数据库、日志、模型权重、导出文件和备份也已加入 `.gitignore`。

测试与评测只能使用人工构造或完成不可逆脱敏的数据。脱敏结果在纳入版本控制前仍需人工复核。

## 日志要求

- 普通运行日志不记录完整问题正文、图片内容、手机号、身份证号、姓名或开放平台凭据。
- 经授权的问答追踪日志可通过 `INTERACTION_LOG_INCLUDE_CONTENT` 保存用户输入和模型输出，但必须与普通运行日志隔离、限制访问并纳入患者数据保留与删除制度。
- 问答追踪日志不得保存图片二进制、原始录音、模型密钥、开放平台凭据或原始访客 ID。
- 使用请求 ID、会话 ID 和错误代码排查问题。
- 生产日志保留期、访问权限和销毁策略必须在上线前由医院确认。

## 提交前检查

```powershell
git status --short
git diff --cached --name-only
git diff --cached
```

重点检查 `.env`、数据库、表格、PDF、图片、音视频、日志和压缩包。不要使用 `git add -f` 绕过忽略规则提交业务资料。

如果密钥已进入提交，必须立即吊销并轮换；如果敏感数据已推送，应停止传播并按项目安全流程清理 Git 历史，仅创建一个后续删除提交是不够的。
