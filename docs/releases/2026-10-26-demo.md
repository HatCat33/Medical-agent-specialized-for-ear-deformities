# Demo 测试版发布记录：2026-10-26

应用版本：`0.4.0`  
阶段分支：`medical_agent_26_10_26`  
建议标签：`v26.10.26-demo`  
状态：用于经理功能演示和阶段验收，不属于医院生产版本。

## 演示范围

- 患者 H5：文字、最多四张图片、拍照、按住说话、SSE 流式回答、随生成播报和历史会话。
- 会话记忆：最近原文、较早内容滚动摘要和最近图片仅在当前会话内复用；新建会话后不继承。
- RAG 管理：FAQ XLSX 增量导入、chunk 管理、Embedding 构建、检索实验、批量评测、版本发布和回退。
- 运行管理：交互次数、提示词版本、声音设置、模型配置总览、手动探活、任务记录与结构化日志。
- 企业微信智能机器人 API 模式：文字、已转写语音、图片输入和流式文本回复。
- 微信客服：加密回调、消息同步、文字/图片/AMR 语音输入和文本回复。

## 数据库变化

- `0004_conversation_memory.py`：当前会话滚动摘要。
- `0005_channel_event_receipts.py`：渠道消息持久化去重。
- `0006_channel_sync_cursors.py`：微信客服增量同步游标。

部署或更新前必须执行：

```bash
cd /root/medical_agent/backend
uv run python scripts/upgrade_database.py
```

当前内嵌任务和渠道运行时按单 API 进程设计，Demo 后端不要启动多个 Uvicorn worker。

## 演示前验证

按 [Demo 演示检查清单](../operations/demo-checklist.md) 执行。至少确认：

- 健康检查、患者端和管理端均能通过 HTTPS 访问。
- 文本流式回答、历史会话、图片问答、语音输入与声音开关可用。
- 管理端已发布正确的知识版本和提示词版本，所需模型探活正常。
- 使用合成问题和非敏感图片，不使用真实患者数据。
- 企业微信渠道只向测试账号开放；微信客服回调成功且同步接口权限正常后再演示。

## 当前限制

- 仅提供健康科普，不输出诊断、处方或手术判定，不能替代医生面诊。
- PDF、视频知识摄取、飞书渠道、独立管理员账号、RBAC、多级审核、限流和集中告警未完成。
- 微信客服的权限和接口频率由企业微信控制；`95012` 等供应商拒绝需要在企业微信后台修正应用与客服账号授权。
- SQLite 适合单机 Demo，不作为多人并发生产数据库；正式部署应迁移 PostgreSQL 并完成备份恢复演练。
- 微信渠道当前以文本回复为主，客户端无法由机器人强制自动播放语音。
