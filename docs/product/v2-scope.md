# 第二版产品范围

更新时间：2026-10-18

版本：`0.2.0`（阶段标签 `v26.10.18`）

## 目标

在第一版文本问答与会话历史基础上，验证患者端多模态咨询和语音交互，同时建立媒体权限、生命周期及运行日志基础能力。

## 已实现

- 单轮最多上传 4 张 JPG、PNG 或 WebP 图片，可同时附带文字描述。
- 图片按钮直接调用系统图片选择器，由手机系统提供拍照或相册来源，并支持多图选择。
- 桌面端额外提供浏览器摄像头预览拍照入口。
- 桌面历史侧栏支持收起、展开和状态记忆，移动端使用抽屉式会话列表。
- 文件签名、单文件大小、总大小和数量校验。
- 图片保存为私有媒体对象，与用户消息和会话绑定。
- 历史会话可重新加载图片，媒体内容接口执行访客归属校验。
- 删除会话时同步删除数据库媒体记录和本地文件。
- 独立 `VISION_*` 配置，采用 OpenAI-compatible 多模态消息格式。
- 图片只进入当前轮视觉请求，不在后续每轮重复传输。
- 文字/语音输入模式切换，按住录音、松开后由服务端 ASR 转写并自动发送，向上滑可取消。
- 独立 `ASR_*` 配置，支持 OpenAI-compatible `/audio/transcriptions` 服务。
- 当前及历史助手回答可使用浏览器中文 TTS 播放和停止。
- 请求 ID、状态码、耗时、附件数量、媒体大小、模型结果和安全结果结构化日志。

## 数据保留

- 用户文字、语音识别后的文字、助手回答和图片附件随会话保存。
- 原始麦克风音频默认不保存；浏览器 TTS 不生成服务端音频文件。
- 日志不记录问题正文、识别文字、模型回答正文或图片内容。
- 当前开发存储为本地私有目录；生产保留期、备份、加密和销毁策略上线前由医院确认。

## 当前限制

- 浏览器录音依赖 MediaRecorder、麦克风授权及 HTTPS 安全上下文；当前本地配置使用 SenseVoice API，生产环境仍需评估医院授权和私有化要求。
- 原始语音历史未实现，当前录音仅在内存中完成一次转写后释放。
- 播报使用系统音色，尚未接入医生授权音色。
- 视觉模型需要单独配置；当前纯文本模型不能处理图片。
- 尚未对图片进行 EXIF 清理、恶意文件沙箱扫描和对象存储迁移。
- 图片相关回答仍只做健康科普，不能依据照片诊断、分型或决定手术方案。

## 下一步

1. 评估并接入医院授权的私有化 ASR，确定原始语音是否保存及保留期。
2. 接入经评测的视觉模型，建立耳畸形图片安全与准确性评测集。
3. 增加 EXIF 清理、病毒扫描、对象存储和异步媒体处理。
4. 接入医院审核后的 FAQ/PDF/视频知识库与可追溯 RAG 引用。
5. 在授权和效果验收后接入医生音色 TTS。
