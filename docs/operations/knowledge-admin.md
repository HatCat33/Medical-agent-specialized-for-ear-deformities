# 知识库管理与检索评测（2026-10-21）

管理端地址 `http://127.0.0.1:5174`，启动方式：

```powershell
cd F:\medical_agent
pnpm dev:admin -- --host 127.0.0.1
```

后端重启后新增接口生效。登录使用 `backend/.env` 的 `ADMIN_API_TOKEN`；浏览器仅在当前会话保存令牌，患者端不带管理令牌。空知识库也能登录。

## 功能与工作流

管理端使用顶部横向导航；手机端导航可横向滚动，不使用侧边栏。

1. **运行总览**：查看患者端 RAG、数据库、检索参数和活动任务，统一展示聊天、视觉、ASR、Embedding、TTS 与探活按钮。TTS 探活试听当前管理员设备，不代表患者设备的可用性。
2. **知识版本**：复制已发布版本为草稿，或创建空白草稿。复制时复用未改变条目的向量；已发布与历史版本的正文只读。
3. **分块管理**：搜索、分页、按向量状态筛选；查看 chunk 的完整问题、其他问法、答案、来源、行号和 ID。新增、编辑、删除仅允许在草稿中进行。
4. **增量导入**：上传 XLSX 到草稿，按去空白且忽略大小写的标准问题匹配。相同内容不更新；变化内容更新；新问题插入；文件中未出现的旧问题保留。删除请在分块管理中操作。修改标准问题本身请编辑原条目，避免被视作新问题。
5. **向量构建**：补全缺失向量仅处理新增或失效的条目；修改问题、其他问法或答案会使该条向量失效。任务立即返回，后台执行，任务页每 3 秒刷新。每批提交，失败后已完成批次保留。更换模型须在草稿全量重建，失败的全量重建需重新全量执行，完成前禁止发布。
6. **检索与评测**：先单条查询检查命中，再标注预期 chunk 或预期无结果，组成评测集。支持 JSON 导入/导出、批量运行、结果持久化和报告导出。
   - 没有评测集时，可选择 20、50 或 100 条，从当前知识版本一键生成。默认使用 XLSX 中的“标准问题”，按分类均衡抽样并自动关联 Chunk ID，不调用模型；也可主动切换为“其他问法”或混合来源。
   - 自动生成的是基础正例集。标准问题与入库文本高度相似，分数通常偏高；正式验收仍应补充真实患者表达和知识库不应回答的负例。
7. **发布**：发布草稿后患者端下一次请求使用新版本；旧版归档。历史版本可重新发布，实现回退。发布会提示缺少向量的条目数量，它们仍可参与关键词检索。
8. **任务与记录**：查看增量构建的进度和错误，查看导入/编辑/删除/发布的记录，以及历史评测报告。删除草稿不会删除其操作记录。
9. **提示词管理**：系统提示词与业务提示词均可修改，同一版本一起保存、发布和回退。沿用登录的管理员令牌验证；已发布内容只读，需先创建草稿。系统提示词默认含医疗约束，修改时应保留医院审核的安全边界；独立的风险规则不会被提示词修改关闭。发布后普通与流式新问答立即使用该版本，问答日志记录版本 ID 和两部分内容共同的 SHA-256。
10. **声音设置**：支持设备语音与云端语音，配置默认播报、音色、语速和音量，支持试听和保存。设备语音还支持语言与音调，云端支持供应商的自定义/克隆音色 ID。患者刷新后获取设置，个人静音偏好优先；设备音色不可用时回退同语言音色。
11. **模型探活**：位于运行总览。地址只显示协议与主机，API Key 只显示是否配置。必须手动触发；视觉发送内置 64×64 PNG（兼容 Qwen3-VL 最小尺寸要求），ASR 发送 250 ms 静音 WAV，可能产生少量调用费用。
12. **系统操作审计**：任务与记录中切换到该标签，查看提示词、模型探活及声音设置的变更详情，不记录密钥。

## 升级现有数据库

在 `backend` 目录执行 `uv run python scripts/upgrade_database.py` 后重启后端。脚本对 SQLite 做一致性备份并检查完整性，备份位于数据库旁的 `backups` 目录；PostgreSQL 请先使用既有数据库备份流程。迁移 `0003` 为已有提示词填入原系统指令、更新组合校验值并创建声音设置表，同时兼容开发启动已创建声音表、迁移中断后已加入系统字段的情况，不覆盖已有设置或系统正文。启动检查发现旧表缺字段时明确提示迁移，不再以“服务正常”状态启动后不断返回接口错误。

## 探活故障诊断

运行总览中，异常结果会自动展开原因、排查建议、HTTP 状态码、供应商错误摘要和请求编号（供应商提供时）。支持区分配置缺失、密钥无效、余额不足、权限不足、接口不存在、限流、超时、连接失败和响应格式错误。探活记录可在“任务与记录 → 系统操作审计”查询。诊断保留脱敏摘要，不存请求密钥、完整供应商响应或患者内容。历史旧探活未包含诊断详情时，重新探活一次。

## 接入自定义云端音色

后端 `.env` 配置：

```dotenv
TTS_BASE_URL=https://你的语音供应商/v1
TTS_API_KEY=你的密钥
TTS_MODEL=供应商的语音合成模型
TTS_VOICE=默认音色ID
TTS_TIMEOUT_SECONDS=30
```

重启后端，在“声音设置”选择“云端语音 · 自定义音色”，填写音色 ID 后试听并保存。支持兼容 `POST /audio/speech` 的服务，要求支持 `model`、`voice`、`input`、`response_format=mp3`、`speed`。自定义或克隆音色需先在供应商处创建并获取 ID，此处不上传声音样本或训练音色。不兼容该协议的供应商需增加适配器。

硅基流动 `FunAudioLLM/CosyVoice2-0.5B` 的预设音色使用完整 ID，例如 `FunAudioLLM/CosyVoice2-0.5B:anna`。声音设置提供预设下拉列表；已有 `TTS_VOICE=anna` 会在请求时补齐该模型前缀，完整自定义/克隆 ID 保持原样。试听、探活、患者播报共用此适配。试听失败直接显示供应商状态、错误码和脱敏摘要，并写入“系统操作审计”。

运行总览分别展示云端语音合成与设备语音，即使患者当前选择设备语音，云端模型仍可单独探活。声音设置中的“探活当前音色”使用未保存表单，不更改患者端配置；探活记录注明使用的模型、音色和配置来源。修改 `backend/.env` 后需重启后端。

设备语音默认只列出本机音色，可打开“显示在线音色”。在线音色依赖浏览器厂商网络，不保证本地可用；浏览器枚举结果不等于探活成功。试听会记录当前页内的失败原因，在线音色启动失败时可回退本机同语言音色，并明确显示替代音色。没有可用本机音色时，可安装系统语言包或配置云端 TTS。管理员电脑试听成功不代表每台患者设备可用。

云端使用同一音色 ID，语速传给供应商，音量由患者播放器控制；浏览器音调参数仅适用于设备语音。音频临时返回并播放，不落盘。设置接口与试听接口要求管理员令牌，患者请求使用访客标识，文本上限 600 字、音频上限 8 MB、最多同时 4 次合成。当前访客标识属于 MVP 访客隔离方式，不等于账户认证；公网大规模开放需在网关配置速率和费用配额。

## XLSX 和 chunk

必需列：`分类`、`标准问题`、`答案内容`；可选列：`其他问法`、`有效日期`。目前读取第一个工作表，其他工作表会给出提示。存在空必填字段或同问题不同答案时拒绝整个导入，不静默选择答案。

单文件不超过 10 MB，解压总大小不超过 50 MB。上传源文件在内存中解析，不保存到公共目录。每条完整 FAQ 是一个 chunk，向量化文本包含问题、其他问法和答案。当前尚未提供 PDF/视频解析和通用长文切块。

## 评测含义

| 指标 | 计算方式 |
| --- | --- |
| 命中率 | 有预期 chunk 的测试中，至少召回一个正确 chunk 的比例 |
| Recall@K | 每条问题召回的正确 chunk 数 / 预期 chunk 数，然后取平均 |
| MRR | 第一个正确结果的排名倒数的平均值，未召回计 0 |
| 无结果准确率 | 标注为无结果的测试中，确实没有检索结果的比例 |
| 通过率 | 所有测试中满足标注条件的比例 |

检索与患者端复用 `retriever.py`。混合模式在向量可用时采用 65% 关键词分数 + 35% 语义分数；服务失败、模型变更或无可用向量时显示降级原因。评测参数只影响当次测试，不修改患者端 `.env`。混合模式会调用配置的 Embedding API；关键词模式不产生模型调用。

预期 ID 必须属于选中的知识版本。复制草稿后 chunk ID 会更新，须重新映射评测标签。指标仅验证检索，不等于生成答案正确率、医学事实一致性或临床审核结果；这些仍需医院审核问题集和人工评价。

## 当前部署边界

- 管理 API 共用管理员令牌，尚未实现多账户、角色权限与审批流。
- 后台任务目前使用单 API 进程的任务执行器，状态和进度写数据库。使用 **一个 worker**；服务重启会把未完成任务标为中断，由管理员重试。多进程/多实例部署前需要迁移到独立任务队列。
- SQLite 和 PostgreSQL 目前都使用 JSON 保存向量、在应用层计算混合排序，适合当前 FAQ 规模。Docker 镜像包含 pgvector，但尚未使用其 HNSW/IVFFlat 索引；不得把部署 PostgreSQL 等同于已经启用原生向量索引。
- 审计记录不存令牌或 API 密钥；评测报告包含管理员输入的问题和命中知识正文，遵循医院的数据保留策略。
- 模型参数与密钥仍由服务器 `.env` 或密钥管理服务控制，管理页面不直接改写 `.env`。更改后重启后端，再手动探活。

数据库切换见 [Docker PostgreSQL 迁移](postgres-migration.md)。
