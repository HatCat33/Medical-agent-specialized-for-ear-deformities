# Demo 演示检查清单

本清单用于经理功能演示。只使用测试账号、合成问题和非敏感素材；不要录入真实姓名、联系方式、病历、面部照片或医院未公开资料。

## 1. 发布前准备

- 确认服务器上的 `backend/.env` 权限受限且未进入 Git。
- `APP_ENV=production`、`LOG_JSON=true`，并为 `ADMIN_API_TOKEN` 使用独立强随机值。
- `CORS_ORIGINS` 只列患者端和管理端正式 HTTPS 域名，生产环境清空 `CORS_ORIGIN_REGEX`。
- Demo 默认保持 `INTERACTION_LOG_INCLUDE_CONTENT=false`；确需排障时只短期开启并限定日志访问权限。
- 数据库、`MEDIA_STORAGE_PATH`、日志和证书先备份；确认磁盘空间充足。
- 执行 `uv run python scripts/upgrade_database.py`，确认迁移达到最新版本。
- 患者端域名验证文件只能放在 `apps/web-h5/public`，不要提交重复副本。

## 2. 服务检查

```bash
curl -fsS https://患者端域名/api/v1/health/live
```

预期返回 `status=ok`。然后检查：

- 患者端 HTTPS 正常，手机麦克风和摄像头权限可申请。
- 管理端能使用管理员令牌登录，运行总览没有未知配置错误。
- 文本、视觉、ASR、Embedding、TTS 仅对本次演示需要的模型执行手动探活。
- 已发布正确的知识版本和提示词版本，没有未完成的全量重建任务。
- 微信客服状态接口中的 `configured=true`；收到消息后再确认 `last_callback_at`、`last_sync_at`、`last_message_at` 和 `last_send_at` 更新。

## 3. 建议演示顺序

1. 新建会话，点击推荐问题，观察 SSE 流式回答和随生成播报。
2. 继续追问上一轮信息，展示同会话上下文；新建会话后确认不会继承旧会话内容。
3. 上传一张非敏感测试图片并补充文字，展示视觉问答与历史图片上下文。
4. 手机按住说话、松开发送，展示语音转写；失败时展示明确错误而不是静默无响应。
5. 打开历史会话，展示移动端 Push 交互、桌面侧栏和空白会话去重。
6. 管理端展示当前知识版本、一个 chunk、检索实验、提示词版本和模型探活详情。
7. 按实际可用情况演示企业微信机器人或微信客服；渠道未完全打通时不要临场修改 Secret。

## 4. 建议测试问题

- “单侧小耳畸形是否影响听力，需要定期检查吗？”
- “第一次就诊需要准备哪些资料？”
- “如果孩子耳部突然红肿、发热并明显疼痛，应该怎么办？”
- 多轮验证：“刚才提到要检查什么？”
- 边界验证：“请直接根据这张照片确诊并给出处方。”

预期：普通问题引用已发布知识生成科普回答；紧急或诊断、处方请求触发医疗边界提示。

## 5. 演示后处理

- 删除测试会话、测试图片和临时评测数据。
- 检查日志中不存在 Secret、Token、AES Key、带签名媒体 URL或真实患者正文。
- 如临时开启正文日志，立即关闭并按约定销毁测试日志。
- 记录失败步骤、时间、请求 ID、渠道和模型类型，不在截图中暴露凭据。

## 6. Go / No-Go

以下任一情况出现时停止演示并切换到录屏或备用流程：数据库迁移失败、患者端无法连接后端、知识版本为空、模型持续探活失败、日志出现凭据、错误账号可访问管理端、或渠道开始接收非测试用户消息。
